# Js

## Inertia v3 frontend conventions (layouts, forms, routes, generated types)
Layouts are resolved centrally in the `layout:` switch in resources/js/app.ts. Pages never import or wrap a layout — they pass props up with `defineOptions({ layout: { breadcrumbs: [...] } })`.

Forms use the Inertia v3 `<Form v-bind="Controller.store.form()" v-slot="{ errors, processing }">` component with uncontrolled `name` / `:default-value` inputs. `useForm` is deliberately used nowhere. Do not install shadcn-vue's `form` component — it pulls in vee-validate and conflicts with this.

URLs come from Wayfinder only: `@/routes/*` for named routes, `@/actions/*` for controller actions. No hardcoded URL strings. Use `toUrl()` from `@/lib/utils` when a plain string is required.

`resources/js/types/generated.d.ts` is generated by `php artisan typescript:transform` from app/Data and app/Enums — never edit it by hand. It is format- and lint-exempt in vite.config.ts.

## Portalled ui/ primitives escape .storefront, and an Inertia post remounts the page
Dialog, Sheet, Popover and friends teleport their content to `document.body`, which is outside StoreShell's `.storefront` wrapper. The brand token remap and the `dark:` neutralisation therefore do not reach them. Restate `class="storefront ..."` on the portalled content element (DialogContent, SheetContent) — that re-establishes the tokens without forking the primitive.

The Vue adapter re-keys the page component on every visit unless `preserveState` is set (`key = preserveState ? key : Date.now()`), so a plain `<Form>` post remounts the page and wipes every ref on it. Any storefront form that must leave page-local state standing — an open dialog, a chosen variant, a quantity — needs `:options="{ preserveScroll: true, preserveState: true }"`.

reka-ui's dialog gives you the focus trap, Escape, outside-click dismissal, `role="dialog"` and the title/description wiring for free. It does NOT restore focus on close for a dialog opened in code: DialogContentModal prevents FocusScope's fallback and focuses `triggerElement`, which only a `<DialogTrigger>` populates. Open programmatically and you must handle `@close-auto-focus` yourself — `event.preventDefault()` then focus the element you remembered.
